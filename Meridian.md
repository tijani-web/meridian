## 0. MISSION

Build a real Kubernetes-native GPU fleet control plane that maximizes GPU utilization and gives researchers a stable inference and workload stack. It must demonstrate, with working code and measured results:

1. **Kubernetes internals**: custom controllers, shared informers, indexers, workqueues, leader election, finalizers, owner refs, server-side apply, scheduling gates, admission webhooks, scheduler framework plugins.
2. **GPU workload scheduling**: gang scheduling, topology-aware placement, fragmentation-aware bin-packing, fair-share queues with borrowing/reclaim, priority preemption.
3. **Fault-tolerant training/eval/RL workloads**: checkpoint-aware preemption, node-failure recovery, elastic restart with generation counters.
4. **Inference serving control plane**: model rollout (canary), warm-up gating, and a request router that uses queue depth, KV-cache pressure, and prefix affinity.
5. **Debuggability**: "why is my job pending?" answered by a CLI backed by real scheduling decision records and traces.
6. **Proof**: reproducible benchmarks with raw data committed, chaos tests, a written postmortem.

Success = every item in §16 (Definition of Done) is verifiably true in the repo.

### 3.1 Key design decisions (each requires an ADR)
- **Admission before pods exist**: the workload controller creates pods with a `schedulingGate` (`meridian.dev/admission`). The queue controller removes the gate only when quota admits the workload. Alternative considered: suspend-style jobs like Kueue. Document the tradeoff.
- **Second scheduler**: pods use `schedulerName: meridian-scheduler`; built on the Kubernetes scheduler framework as an out-of-tree plugin set. Reference `sigs.k8s.io/scheduler-plugins` for structure; do not copy code verbatim without attribution.
- **Preemption lives at the workload layer** (queue controller), not in the scheduler's default PostFilter, so it can be checkpoint-aware. The scheduler's default preemption is disabled for Meridian pods. ADR required.
- **GPU resource model**: extended resource `nvidia.com/gpu` plus node labels for topology. ADR must explain the device-plugin model vs Dynamic Resource Allocation (DRA) and what migration would involve (DRA support itself is a stretch goal, §15).
- **Decision records**: the scheduler records, per pod, per-node filter rejection reasons and score breakdowns in a bounded in-memory ring buffer exposed over HTTP, and summarizes into Events and Pod/Workload conditions. This powers `explain`.

## 5. APIs (CRDs)

Define with kubebuilder markers, full OpenAPI validation, printer columns, status subresource, and conditions (`metav1.Condition`). All spec fields documented. Immutability enforced by webhook or CEL validation rules.

### 5.1 `GPUQueue` (cluster-scoped)
Represents a team/tenant quota.
```
spec:
  namespaceSelector            # which namespaces may submit to this queue
  nominalQuota: {gpuType: count}      # guaranteed GPUs
  borrowingLimit: {gpuType: count}    # max extra GPUs borrowable from idle capacity
  lendingLimit:   {gpuType: count}    # max nominal GPUs lendable to others
  priority: int32                     # queue-level tie-break
  preemption: {reclaimWithinQueue: bool, reclaimBorrowed: bool, checkpointGracePeriod: duration}
status:
  usage: {gpuType: {used, borrowed, lent}}
  pendingWorkloads, admittedWorkloads: int
  conditions: [...]
```

### 5.2 `GPUWorkload` (namespaced)
A gang of pods: training, eval, or RL job.
```
spec:
  queueName: string
  priorityClassName: string
  kind: Training | Eval | RL
  gang: {size: int32, minAvailable: int32}          # all-or-nothing by default
  gpusPerPod: int32; gpuType: string
  topology: {preference: SameNVLinkDomain|SameRack|SameZone|None, required: bool}
  podTemplate: corev1.PodTemplateSpec
  checkpoint: {enabled: bool, interval: duration, ackTimeout: duration, path: string}
  restartPolicy: {maxRestarts: int32, backoff: duration, elastic: {minSize, maxSize}}
status:
  phase: Pending|Queued|Admitted|Scheduling|Running|Checkpointing|Preempting|Recovering|Succeeded|Failed
  generation: int64                 # restart generation counter
  admittedAt, startedAt, lastCheckpointAt: time
  assignment: [{pod, node, gpus}]
  history: [{seq, time, from, to, reason, message}]   # bounded, ordered by seq
  conditions: [Admitted, Scheduled, Running, CheckpointHealthy, ...]
```

### 5.3 `InferenceDeployment` (namespaced)
```
spec:
  model: {name, uri, revision}
  runtime: {image, args, port, metricsPath}
  replicas: int32; resources: gpusPerReplica
  rollout: {strategy: Canary|BlueGreen, steps: [{weight, pauseSeconds, analysis}], maxUnavailable}
  warmup: {readinessPromptPath/probe, minWarmRequests}
  routing: {strategy: LeastQueue|KVAware|PrefixAffinity, loadShedding: {maxQueueDepth, priorityClasses}}
status:
  revisions: [{name, weight, readyReplicas, warm}]
  conditions, observedGeneration
```

### 5.4 Webhooks
Validating + defaulting webhooks for all three kinds: immutable fields, gang size ≤ quota possibility check, `minAvailable ≤ size`, topology/type validity, queue existence, checkpoint settings coherent. TLS via cert-manager in the Helm chart. Test with envtest.

## 6. COMPONENT SPECS

### 6.1 Workload controller (`internal/controller/workload`)
Table-driven FSM in `internal/fsm` (pure, unit-testable) driven by the reconciler.
- States/transitions: `Pending → Queued → Admitted → Scheduling → Running → (Checkpointing|Preempting|Recovering) → Succeeded|Failed`. Every transition is a **crash-recovery checkpoint**: persisted to status via server-side apply **before** side effects are considered complete, and each side effect is idempotent and re-derivable from status + observed cluster state.
- Creates gated pods (labels `meridian.dev/workload`, `meridian.dev/gang-size`, `meridian.dev/generation`), owner refs for GC, finalizer for cleanup/accounting release.
- Shared informer cache with **custom field indexers** (pod → workload, node → pods) — required, document in a design doc.
- Rate-limited workqueue with per-item backoff; conflict handling via requeue (no blind retries); max concurrent reconciles configurable.
- Leader election via Lease; HA with 2 replicas; failover test in Phase 12.
- Emits Events and conditions with machine-readable reasons.

### 6.2 Queue / admission controller (`internal/controller/queue`)
- Computes admission per queue: nominal quota, borrowing from idle capacity, lending, and **fair-share** across queues (DRF-lite over GPU counts; document the exact algorithm in `docs/design/fair-share.md` with worked examples).
- Admits a workload atomically (whole gang) by reserving quota, then removes the scheduling gate on all its pods.
- **Reclaim**: when a queue needs its nominal quota back, picks victim workloads (borrowed first, lowest priority, most recently admitted — document tie-break) and starts checkpoint-aware preemption (§6.5).
- Queue position and reasons exposed in status for `explain`.
- Property-based tests (e.g. `rapid`/`gopter`) for invariants: usage never exceeds nominal+borrowed limits; no gang is partially admitted; reclaim terminates.

### 6.3 Scheduler (`cmd/scheduler`, `internal/scheduler`)
Out-of-tree plugins on the scheduler framework. Required extension points and behavior:
- **QueueSort**: priority, then workload admission time (FIFO within priority), keeping gang members adjacent.
- **PreFilter**: reject early if gang metadata invalid or gang can't possibly fit cluster-wide (with a clear reason).
- **Filter**: GPU type/count fit, health taints, topology *required* constraints.
- **Score** + **NormalizeScore**: combine
  - *best-fit / anti-fragmentation*: prefer nodes where leftover free GPUs after placement is small but usable; avoid putting 1-GPU pods on empty 8-GPU nodes when partially-used nodes fit;
  - *topology affinity*: prefer nodes sharing the NVLink domain/rack/zone already chosen for the gang;
  - *spread/health*: mild penalty for recently-unhealthy nodes.
  Weights configurable via `KubeSchedulerConfiguration` plugin args. Exact formulas documented in `docs/design/scoring.md` with worked examples.
- **Reserve / Unreserve**: track tentative GPU assignments per gang.
- **Permit**: gang scheduling. Pods wait (`Wait` status) until `minAvailable` members have reserved nodes; on timeout, unreserve and reject all. No partial gang binds. Handle gang member failure and late arrivals correctly.
- **PreBind/Bind**: default bind; annotate assignment for `explain`.
- Topology source: node labels `meridian.dev/nvlink-domain`, `meridian.dev/rack`, `topology.kubernetes.io/zone`, GPU type label. Document the label contract.
- **Decision recorder** (`internal/scheduler/decisions`): per-pod record of node → (filter result or score breakdown) in a bounded ring buffer, HTTP endpoint `/decisions?namespace=&pod=`, plus summarized Events. Must have a documented memory bound.
- Metrics: attempts by result, scheduling latency histogram, gang wait time, fragmentation ratio gauge.

### 6.4 Node health (`internal/agent`, `internal/controller/health`)
- **Agent** (DaemonSet on GPU nodes) with a `HealthSource` interface and **two real implementations**: `nvml` (go-nvml) and `dcgm-exporter` scraper (Prometheus text format parse). Detects: XID errors (classify fatal vs recoverable using a documented table), ECC uncorrectable errors, thermal throttling, GPU fell off bus, missing devices.
- Publishes node conditions (`meridian.dev/GPUHealthy`) and applies taints (`meridian.dev/gpu-unhealthy:NoSchedule` / `NoExecute` depending on severity). Flap damping with hysteresis (documented thresholds).
- **Health controller** reconciles node health → affected workloads → `Recovering` transition → reschedule with generation bump. Cordon/drain is checkpoint-aware where time allows.
- Tests: fault-injector emits real DCGM-format metrics → agent parses → taint applied → workload recovers on a healthy node. Run on kind (real agent pods) and via direct condition patching on KWOK nodes for scale.

### 6.5 Checkpoint protocol and preemption (`internal/checkpoint`, `pkg/ckptclient`)
Defined in `docs/design/checkpoint-protocol.md`. Minimum:
- Controller requests: annotates pod(s) `meridian.dev/checkpoint-request: "<generation>:<seq>"`.
- Trainer-side library `pkg/ckptclient` (Go) watches its own pod annotations via downward API/in-cluster watch, invokes a user callback, and acks by patching `meridian.dev/checkpoint-ack` with the completed path and step.
- Controller waits for acks from all gang members up to `ackTimeout`, then evicts. On timeout → force evict, mark `CheckpointHealthy=False`, record in history.
- Resume: new generation pods receive `MERIDIAN_RESUME_FROM` env pointing at the last acked checkpoint.
- Elastic restart: if `elastic` allowed and capacity short, restart at a smaller valid size.
- **Straggler detection**: gang members with no heartbeat/progress annotation within a window flagged; documented policy (alert vs restart).
- Provide `test/e2e/trainer` — a real small Go workload using `ckptclient` that writes real checkpoint files to a volume and genuinely resumes from them (verify resumed step ≥ last acked step).

### 6.6 Inference control plane (`internal/controller/inference`)
- Reconciles `InferenceDeployment` into per-revision Deployments + Services, scheduled with Meridian scheduler (GPU-aware).
- **Warm-up gating**: a replica isn't marked warm/eligible for traffic until the warm-up probe passes; router only sees warm replicas.
- **Canary rollout**: stepwise weights; automated hold/rollback based on analysis (error rate and TTFT p99 from router metrics via Prometheus API query). Rollback is tested.
- Publishes the routing table (endpoints, revision weights, strategy) to the router through a real mechanism (EndpointSlice watch + a ConfigMap/CRD status), not hard-coded config.
- *Stretch*: node-local weight prefetch (§15).

### 6.7 Inference router (`cmd/router`, `internal/router`)
Reverse proxy for OpenAI-compatible endpoints, streaming (SSE) passthrough correct.
- Replica pool built from watched endpoints; scrapes each replica's `/metrics` (queue depth, running requests, KV-cache usage — names per pinned vLLM version) on a short interval with staleness handling.
- Strategies (pluggable, benchmarked against each other):
  1. `RoundRobin` (baseline), 2. `LeastQueue`, 3. `KVAware` (avoid replicas above KV-cache pressure threshold), 4. `PrefixAffinity` (bounded-load consistent hashing on a hash of the prompt prefix, falling back to LeastQueue when the preferred replica is overloaded).
- **Load shedding**: reject with 429 + `Retry-After` when estimated queue exceeds the threshold; priority-class aware (low priority shed first).
- Handles replica failure mid-stream and connection draining on rollout.
- Metrics: TTFT, time-per-output-token, route decisions by strategy, shed count, per-replica load.
- Correctness tests: streaming integrity, backpressure, cancel propagation, replica-removal during traffic.

### 6.8 Explainability (`internal/explain`, `cmd/meridianctl`)
`meridianctl explain workload <name> -n <ns>` must answer, from **real data**, in order:
1. Current phase and how long it has been there.
2. Queue status: position, quota used/limit/borrowable, what's blocking admission (and which workloads hold the quota).
3. If gated: which gate and why.
4. If scheduling: per-node rejection summary grouped by reason (e.g. "37 nodes: insufficient nvidia.com/gpu; 12 nodes: topology SameNVLinkDomain unmet; 4 nodes: unhealthy taint") and the best-scoring candidates with score breakdown.
5. If waiting at Permit: how many gang members reserved vs needed, time until timeout.
6. If preempted/recovering: the ordered history with causes (who preempted, checkpoint ack durations, node fault).
Also `meridianctl status cluster` (GPU utilization, fragmentation, queue summary) and `meridianctl explain inference <name>`.
- **Tracing**: OpenTelemetry spans across admission → gate release → scheduling cycle → permit wait → bind → container start, linked by workload UID; exported over OTLP. Events within a workload carry a monotonically increasing `seq` so causal ordering is unambiguous.
- *Stretch*: export events to Causa for causal ordering (§15).

### 6.9 Observability (`internal/telemetry`, `dashboards/`)
Prometheus metrics (prefix `meridian_`) at minimum:
`scheduler_attempts_total{result}`, `scheduler_latency_seconds`, `gang_wait_seconds`, `queue_wait_seconds{queue}`, `gpu_allocated_ratio`, `gpu_fragmentation_ratio`, `preemptions_total{reason}`, `checkpoint_ack_seconds`, `workload_phase_transitions_total`, `node_health_transitions_total`, `router_ttft_seconds`, `router_route_total{strategy}`, `router_shed_total{priority}`, controller workqueue depth/latency (controller-runtime defaults retained).
- Grafana dashboards as JSON in `dashboards/`: fleet utilization, queues, scheduler, node health, inference router.
- Define SLOs in `docs/design/slos.md` (e.g. scheduling decision latency, admission latency, TTFT p99 under a defined load) and alerting rules as PrometheusRule YAML. SLO targets must come from measured baselines, not guesses.

## 8. BENCHMARKS (`bench/`)

Methodology doc: `bench/METHODOLOGY.md` — hardware, versions, seeds, warm-up, repetitions (≥5), reported as median + spread, scripts to reproduce.

### 8.1 Scheduler/queue (simulated fleet via KWOK)
- Workload traces: synthetic generator in `tools/trace-gen` (documented distribution: mix of 1/2/4/8-GPU jobs, gang jobs of 4–64 GPUs, mixed priorities, multiple queues) with fixed seeds. Additionally a replay mode for user-supplied traces.
- Compare: **default kube-scheduler** vs **Meridian** (and **Kueue + default scheduler** if installable in the environment; if not, state so in LIMITATIONS).
- Metrics: GPU allocation ratio over time, fragmentation ratio, mean/p95/p99 queue wait, gang start latency, number of partially-started gangs (must be 0 for Meridian), scheduling throughput (pods/sec) at 500 and 2000 nodes, preemption count and wasted GPU-seconds.

### 8.2 Fault tolerance
- Inject node GPU faults and node loss during running checkpointed jobs. Report: time to detect, time to reschedule, steps lost vs. last checkpoint, % of jobs that resumed correctly.

### 8.3 Inference router
- Workloads: unique prompts, and shared-prefix prompts (e.g. 70% sharing a long system prompt). Open-loop Poisson arrivals at multiple rates.
- Compare the four strategies: TTFT p50/p99, throughput, shed rate, and (with vllm-emu or real vLLM) prefix-cache-hit rate where exposed.
- **Optional real-GPU run**: one short session using `terraform/gpu-demo` with real vLLM, results stored separately and labeled "real GPU". Include teardown instructions and a cost estimate in the runbook. If not executed, state that in LIMITATIONS.
